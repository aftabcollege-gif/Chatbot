# راهنمای اجرا و دیپلوی — حالت آفلاین (Offline-First)

این سامانه طوری طراحی شده که **بدون اینترنت** اجرا شود: مدل زبانی (LLM) و مدل
Embedding هر دو محلی (llama.cpp / GGUF) هستند و یک **کیل-سوییچ شبکه** تضمین می‌کند
هیچ درخواستی به اینترنت ارسال نشود (`AI_MODE=offline` پیش‌فرض).

> **کاربران ویندوز بدون Node.js:** یک فایل `Setup.exe` کاملاً آفلاین (شامل Node،
> مدل‌ها، OCR و پایگاه‌داده) از تب **Releases** قابل دریافت است. نحوهٔ ساخت آن در
> [`portable_setup/README.md`](portable_setup/README.md) و راهنمای اجرای نسخهٔ
> قابل‌حمل در [`portable_bild/README.md`](portable_bild/README.md) آمده است.

## پیش‌نیازها

- Node.js 20.9+ (نسخهٔ ۲۲ توصیه می‌شود)
- **بدون PostgreSQL**: پایگاه‌داده (PGlite + pgvector) داخل خود برنامه است و در
  `storage/database` ساخته می‌شود
- یک بار دسترسی به اینترنت برای دانلود مدل‌ها (فقط هنگام نصب)

## نصب و راه‌اندازی

```bash
# 1) نصب وابستگی‌ها
npm install

# 2) دانلود مدل‌های محلی (فقط یک بار، با اینترنت)
node scripts/install-model.mjs        # LLM (Qwen2.5-1.5B) + Embedding (bge-m3) + OCR
# یا جداگانه:
node scripts/install-model.mjs --llm --embedding --ocr

# 3) تنظیمات
cp .env.example .env
# سپس در .env مقدار JWT_SECRET (حداقل ۳۲ کاراکتر) و JOB_SECRET را بگذارید.
# (PORTABLE_DATABASE_DIR مسیر پایگاه‌دادهٔ تعبیه‌شده است؛ پیش‌فرض ./storage/database)

# 4) ساخت و اجرا
npm run build
npm start
```

- Migration های دیتابیس هنگام اولین اجرای سرور به‌صورت خودکار اعمال می‌شوند؛ تا
  پایان آن‌ها `/api/health` کد ۵۰۳ برمی‌گرداند (مناسب برای بررسی آمادگی).
- کاربر مدیر اولیه `admin` با رمز `ChangeMe123!` ساخته می‌شود؛ رمز را بلافاصله
  عوض کنید. صفحهٔ راه‌اندازی (`/setup`) برای ساخت سازمان/کاربر مدیر دلخواه است.

### تست‌های خودکار

```bash
npm run typecheck && npm run build
node portable_setup/stage-bundle.cjs . /tmp/stage --platform linux --arch x64 --skip-models
node portable_setup/smoke-test.cjs /tmp/stage          # ۱۶ بررسی راه‌اندازی
node portable_setup/api-regression.cjs /tmp/stage      # ۶۳ بررسی رفتاری end-to-end
```

هر دو اسکریپت، بستهٔ ساخته‌شده را با پایگاه‌دادهٔ موقت روی پورت آزاد اجرا می‌کنند و
پس از اتمام همه‌چیز را پاک می‌کنند؛ همین دو مرحله در CI هم اجرا می‌شوند.

## اجرا بدون اینترنت

بعد از نصب مدل‌ها، کل سیستم آفلاین کار می‌کند:

- `AI_MODE=offline` (پیش‌فرض): کیل-سوییچ شبکه هر درخواست به سرویس‌های هوش
  مصنوعی خارجی (OpenAI و...) را قبل از اتصال مسدود می‌کند.
- اگر مدل Embedding در دسترس نباشد، جستجو به حالت «کلمات کلیدی» (tsvector با
  نرمال‌سازی ي/ك/ی/ک، ارقام و حذف ایست‌واژه‌های فارسی) تنزل می‌کند؛ اگر مدل LLM
  در دسترس نباشد، پاسخ «استخراجی از منابع» داده می‌شود.
- هیچ fallback خودکاری به کلاد وجود ندارد.

## واردکردن انبوه اسناد (هزاران تا صدها هزار فایل)

آپلود تک‌فایلی برای آرشیوهای بزرگ مناسب نیست. دو راه سریع‌تر وجود دارد:

1. **پنل مدیریت → تب «پردازش و واردکردن»**: مسیر یک پوشه روی سرور را وارد کنید؛
   همهٔ فایل‌های پشتیبانی‌شده به‌صورت بازگشتی ثبت و در صف پردازش قرار می‌گیرند
   (فایل‌های تکراری با SHA-256 حذف می‌شوند). وضعیت صف و کارگر پس‌زمینه به‌صورت
   زنده نمایش داده می‌شود.
2. **خط فرمان** (سریع‌ترین؛ در حالی که برنامه متوقف است):

   ```bash
   # فقط شمارش، بدون ذخیره
   npm run import -- /path/to/archive --dry-run
   # ثبت + پردازش در همین پروسه با ۴ کارگر هم‌زمان
   npm run import -- /path/to/archive --process --concurrency 4
   # فایل‌ها را کپی نکن، در محل ارجاع بده (پوشه باید ثابت بماند)
   npm run import -- /path/to/archive --mode link --process
   ```

   PGlite تنها یک پروسهٔ نویسنده را می‌پذیرد؛ بنابراین `--process` را وقتی
   برنامه اجراست به‌کار نبرید (بدون `--process` فقط صف پر می‌شود و کارگر
   داخل برنامه آن را تخلیه می‌کند).

نکات ظرفیت:

- تعداد کارگرهای هم‌زمان: `INGEST_CONCURRENCY` (برای متن خالص روی ۸ هسته ۴–۸؛
  با Embedding روی CPU ۱–۲، چون مدل گلوگاه است).
- اگر مدل Embedding نصب نباشد، ستون بردار `NULL` می‌ماند و جستجو کلیدواژه‌ای
  (با نرمال‌سازی فارسی و حذف ایست‌واژه) است. بعد از نصب مدل، بردارها را با
  `npm run reindex` پر کنید (به‌صورت دسته‌ای و قابل ازسرگیری).
- درج در ایندکس HNSW در PGlite حدود ۲۰ms برای هر بردار است؛ برای بارگذاری
  اولیهٔ چند میلیون قطعه، ایندکس را قبل از reindex حذف و بعد از آن بسازید
  (اسکریپت `npm run rag:bench` همین کار را برای سنجش انجام می‌دهد).
- سنجش تأخیر جستجو با پیکرهٔ مصنوعی: `npm run rag:bench -- --chunks 50000`.

## معماری

- **فرانت/API:** Next.js 16
- **دیتابیس:** PostgreSQL تعبیه‌شده (PGlite) + pgvector با ایندکس HNSW؛
  جستجوی ترکیبی (بردار + کلیدواژهٔ فارسی نرمال‌شده) با RRF و بازچینش
- **LLM محلی:** Qwen2.5-1.5B-Instruct (GGUF Q4_K_M) با node-llama-cpp
- **Embedding محلی:** BAAI/bge-m3 (GGUF Q8_0, 1024 بعد)
- **OCR:** Tesseract.js (فارسی + انگلیسی، کاملاً محلی)

## ماژول‌ها

- احراز هویت (JWT + Session + RBAC)
- چت هوشمند با RAG و استناددهی
- مدیریت اسناد (آپلود → استخراج → OCR → chunk → index)
- پایگاه دانش و تجربیات سازمانی با گردش‌کار تأیید
- جستجوی ترکیبی (semantic + keyword)
- پنل مدیریت، لاگ حسابرسی، تنظیمات سیستم، صف پردازش پس‌زمینه
