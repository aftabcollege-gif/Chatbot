# رفع مشکل تکرار پاسخ — بدون نصب مجدد

این راهنما مشکل «گیر کردن پاسخ و تکرار بی‌پایان یک عبارت» را روی نسخه‌ای که
**همین الان نصب کرده‌اید** برطرف می‌کند. نیازی به دانلود دوباره، نصب مجدد یا
بیلد گرفتن نیست.

---

## چرا فقط کانفیگ را عوض می‌کنیم؟

بکند پایتون با PyInstaller **فریز (frozen)** شده و داخل `backend-server.exe`
بسته‌بندی است. بنابراین تغییر فایل‌های `.py` هیچ اثری روی نسخهٔ نصب‌شده ندارد
مگر اینکه دوباره بیلد شود.

ولی خبر خوب: دقیقاً همان چیزهایی که باعث حلقه می‌شوند، بیرون از آن exe و
روی دیسک قرار دارند و در زمان اجرا خوانده می‌شوند:

| فایل | نقش |
|---|---|
| `config\default.yaml` | هنگام بالا آمدن برنامه خوانده می‌شود |
| `config\system-prompt.txt` | در **هر درخواست** دوباره خوانده می‌شود |
| `llm\llama-server.exe` | با آرگومان‌های خط فرمان اجرا می‌شود |

پس همه چیز از همین سه نقطه قابل اصلاح است.

---

## روش ۱ — اسکریپت خودکار (پیشنهادی)

۱. برنامه را **کاملاً ببندید** (سینی کنار ساعت را هم چک کنید).
۲. روی `apply-hotfix.ps1` راست‌کلیک نکنید؛ به‌جای آن PowerShell را
   **به‌عنوان Administrator** باز کنید.
۳. این را اجرا کنید:

```powershell
powershell -ExecutionPolicy Bypass -File apply-hotfix.ps1
```

اگر مسیر نصب پیدا نشد، خودتان بدهید:

```powershell
powershell -ExecutionPolicy Bypass -File apply-hotfix.ps1 -InstallDir "C:\Program Files\EnterpriseAI"
```

برای برگرداندن همه چیز به حالت اول:

```powershell
powershell -ExecutionPolicy Bypass -File apply-hotfix.ps1 -Revert
```

اسکریپت قبل از هر تغییر، از فایل‌های اصلی در پوشهٔ `hotfix-backup` نسخهٔ
پشتیبان می‌گیرد.

---

## روش ۲ — دستی (اگر اسکریپت اجرا نشد)

برنامه را ببندید، بعد فایل `config\default.yaml` را با Notepad باز کنید و
این چهار مقدار را عوض کنید:

```yaml
llm:
  temperature: 0.3        # قبلاً 0.1 بود
  max_tokens: 700         # قبلاً 2048 بود

reranker:
  top_k: 2                # قبلاً 5 بود

rag:
  chat_history_max_tokens: 200   # قبلاً 1500 بود
```

> ⚠️ دقت کنید کلید درست `reranker.top_k` است (بخش `reranker` در سطح بالا).
> کلید `rag.reranker_top_k` در نسخهٔ نصب‌شده **اصلاً خوانده نمی‌شود**.

سپس در انتهای `config\system-prompt.txt` این را اضافه کنید:

```
قواعد ضد تکرار (مهم):
- هرگز یک عبارت یا جمله را تکرار نکن. هر جمله باید اطلاعات تازه اضافه کند.
- پاسخ را کوتاه نگه دار؛ حداکثر چند بند کوتاه.
- وقتی پاسخ کامل شد، بلافاصله متوقف شو و چیزی اضافه ننویس.
- اگر اطلاعات کافی در منابع نیست، فقط یک جمله بنویس و تمام کن.
```

هر دو فایل را با انکودینگ **UTF-8** ذخیره کنید.

## هر تغییر چه کاری می‌کند؟

### ۱. `temperature: 0.1 → 0.3`
مهم‌ترین اهرمی که فقط از طریق کانفیگ در دسترس است. دمای ۰.۱ یعنی نمونه‌برداری
تقریباً حریصانه (greedy)؛ وقتی جریمهٔ تکرار هم خاموش باشد، همین ترکیب دقیقاً
همان شرایطی است که مدل کوچک در آن قفل می‌کند و یک عبارت را تا ابد تکرار می‌کند.

### ۲. `max_tokens: 2048 → 700` و `reranker.top_k: 5 → 2`
اینجا مهم‌ترین کشف ماست. لانچر برنامه موتور را این‌طور اجرا می‌کند:

```
llama-server.exe --ctx-size 4096 --parallel 2
```

اما llama.cpp پنجرهٔ کانتکست را **بین اسلات‌ها تقسیم می‌کند**:

```
n_ctx_slot = n_ctx / n_parallel = 4096 / 2 = 2048
```

یعنی هر درخواست در عمل فقط **۲۰۴۸ توکن** دارد، نه ۴۰۹۶. با تنظیمات قبلی:

```
۵ قطعه × ۵۱۲ کلمه (≈۲.۳ توکن هر کلمه) + پرامپت سیستم + ۲۰۴۸ رزرو خروجی
≈ ۴۷۶۳ توکن  ❌  در برابر سقف واقعی ۲۰۴۸
```

llama.cpp ابتدای پرامپت — یعنی خود دستورالعمل‌ها — را دور می‌ریخت. مدل بدون
قانون می‌ماند و شروع به پرت‌گویی و تکرار می‌کرد. این توضیح می‌دهد چرا منابع
بی‌ربط (تعلیق قرارداد، کار اضافی) به سؤال مرخصی چسبانده می‌شدند.

### ۳. جریمهٔ تکرار روی موتور LLM (علت ریشه‌ای)
بکند در درخواستش هیچ فیلد `repeat_penalty` نمی‌فرستد، و پیش‌فرض llama.cpp
برابر `1.0` یعنی **غیرفعال** است.

اسکریپت یک «شیم» (رابط واسط) کوچک جای `llama-server.exe` می‌گذارد که موتور
اصلی را با این پرچم‌ها صدا می‌زند:

```
--repeat-penalty 1.15  --repeat-last-n 256
--frequency-penalty 0.3  --presence-penalty 0.3
```

این کار درست است چون در سورس llama.cpp نسخهٔ b3800 (فایل `server.cpp`) داریم:

```cpp
slot.sparams.penalty_repeat = json_value(data, "repeat_penalty",
                                         default_sparams.penalty_repeat);
```

یعنی وقتی درخواست این فیلد را نداشته باشد، مقدار پیش‌فرضِ سرور (همانی که ما
با خط فرمان می‌دهیم) اعمال می‌شود.

### ۴. `--parallel 2 → 1`
شیم این را هم اصلاح می‌کند. این برنامه تک‌کاربره است و اسلات دوم هیچ سودی
ندارد، ولی نصف کانتکست را می‌بلعد. با تبدیلش به ۱، کل ۴۰۹۶ توکن آزاد می‌شود:

```
۲ قطعه + پرامپت سیستم + ۷۰۰ خروجی ≈ ۳۴۱۱ توکن  ✅  از ۴۰۹۶
```

## اگر شیم نصب نشد چه می‌شود؟

اسکریپت برای ساخت شیم به کامپایلر C# ویندوز (`csc.exe`) نیاز دارد که معمولاً
همراه .NET Framework روی ویندوز ۱۰/۱۱ هست. اگر پیدا نشد، اسکریپت **موتور را
دست‌نخورده باقی می‌گذارد** و فقط تغییرات کانفیگ را اعمال می‌کند.

در آن حالت هم وضعیت به‌مراتب بهتر می‌شود (دما ۰.۳ و پرامپت کوچک‌تر)، ولی
جریمهٔ تکرار در سطح موتور اعمال نشده و احتمال حلقه صفر نمی‌شود.

---

## بررسی اینکه اعمال شده یا نه

بعد از اجرا، برنامه را باز کنید و همان سؤال مرخصی را بپرسید. انتظار می‌رود:

- پاسخ دیگر یک عبارت را بی‌پایان تکرار نکند
- تعداد منابع از ۵ به ۲ کاهش پیدا کند (منابع مرتبط‌تر)
- پاسخ کوتاه‌تر و متمرکزتر باشد

---

## محدودیت‌ها — لطفاً بخوانید

- این هات‌فیکس **فقط** پارامترهای زمان اجرا را عوض می‌کند. اصلاحات کد
  (سپر تشخیص حلقه، فرمول اطمینان، فیلتر آستانهٔ ارتباط) داخل exe فریزشده
  هستند و تا بیلد بعدی فعال نمی‌شوند.
- درصد «اطمینان» همچنان با فرمول قدیمی (میانگین) محاسبه می‌شود. با
  `top_k=2` عدد نمایش‌داده‌شده به‌طور طبیعی بالاتر و واقعی‌تر می‌شود، ولی
  فرمول اصلاح‌شده در این هات‌فیکس نیست.
- `rag.chunk_size` فقط روی اسنادی اثر دارد که **از این به بعد** آپلود شوند؛
  قطعه‌های موجود در پایگاه داده دوباره تکه‌بندی نمی‌شوند.
- من نتوانستم این را روی ویندوز با مدل واقعی تست کنم (در محیط من نه ویندوز
  هست نه فایل GGUF). منطق پچ‌کردن YAML و ساخت آرگومان‌های شیم را شبیه‌سازی و
  تست کرده‌ام، ولی اجرای نهایی روی سیستم شما باید تأیید شود.
- اگر مدل ۷B را نصب کرده‌اید، `reranker.top_k` را می‌توانید روی ۳ بگذارید.
  برای مدل ۱.۵B همان ۲ بهتر است.
